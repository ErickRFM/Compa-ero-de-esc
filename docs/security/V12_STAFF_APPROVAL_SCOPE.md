# V12 staff approval and scoped tutor authority

A verified teacher or tutor registration produces a pending application, not a privileged role or a group. Previously verified pending registration intents are deterministically materialized as applications during an authorized decision. Supplementary tutor applications are available to an active verified teacher in their actual institution; submitting one does not change grants or invalidate the current teacher session.

`GET /admin/accounts` returns actual users, applications and metrics within the native operator's institution and explicit delegated capability. `POST /admin/accounts/{accountId}/staff-approval` requires a persisted request, current verified applicant, enabled institution and an exact MFA proof. Approving Tutor requires one to twenty distinct real groups with matching institution/period and explicit start/end within group validity. Preference fields never authorize a group. Teacher approval preserves existing roles and does not create tutor assignments.

Account decision, new role, authority revision, per-role generation and secret-free decision audit are committed with one account compare-and-set. Tutor assignments are then persisted through the existing `TutorAssignmentService` using deterministic operation IDs. This is an idempotent continuation, not a multi-document transaction. If assignment persistence fails, no assignment means no tutorated data access; retry the exact original actor/resource/operation/payload while its proof is current. Do not alter payload on a retry. An expired proof requires a new current step-up for that same command. A later suspension, role revocation or generation change prevents continuation.

`POST /auth/staff-applications` submits a supplementary tutor request; GET returns only the native owner's requests. Pending applicants may read their own request but cannot access academic or administrative endpoints. Session source is resolved from the persisted native refresh family, never from matching an institutional user ID.

`POST /tutoring/assignments` and PATCH `/tutoring/assignments/{assignmentId}/revoke` require delegated academic administration and real MFA for the exact scoped command. Creation requires a verified active Tutor, current role generation and actual group metadata. Revocation stores operator, operation and payload digest; an unrelated operation cannot reuse its success. A revoked assignment ID is never overwritten. Different scopes must be explicitly revoked and recreated.

Tutor reads require current native authority, an active group/assignment, matching institution/period, current grant generation and non-expired validity. Private case notes require the actual Tutor assignment even for Super Admin. Revoking and regranting Tutor never revives an older generation's assignments; unrelated Teacher changes retain the Teacher grant. Unknown legacy group or assignment metadata cannot grant tutor access and awaits protected explicit migration; do not infer institution or academic period from names.

Representative appointment/revocation now retains the complete authority snapshot. Its overview requires actual member/assigned tutor/scoped administration, and students see only their own pending invitation. Candidate accounts must be verified students belonging to that group. Existing accept/decline/revoke behavior is preserved.

Automated fixtures explicitly seed only isolated test identities, capabilities, groups and periods. Test-only operator helpers execute actual TOTP, AES-GCM and proof persistence rather than fake MFA verification. This delivery is still being extended with protected group metadata migration and remaining legacy academic administrator checks before review/merge; production provisioning is not complete.

## Explicit group migration
`POST /academic/groups/{groupId}/scope` requires a verified current native institutional MANAGE_ACADEMICS capability and command-bound real MFA. Only SUPER_ADMIN may supply an unknown legacy institution. A known institution is immutable because moving existing memberships, cases and classes would cross tenants. An enabled directory entry and explicitly linked matching native member institutions are required; unlinked legacy data blocks migration rather than guessing. Single-document scope revision/audit CAS is idempotent for the exact actor/operation/payload and tested with 24 independent real Mongo repository instances.

Tutor grants bind the group's monotonically increasing scopeRevision as well as the tutor's role grant generation. Restoring an old period name does not restore old access. Missing persisted assignment group revisions fail closed and require explicit revocation/reassignment after migration; there is no silent rewrite of historical grants. Group creation and member assignment require scoped MFA. Creation records the initial scope audit, actual dates and tenant; member linking requires an actual verified active native student in the same institution. No operation claims SIS identity verification.

## Existing native academic services
Classroom assignment requires actual verified live teacher identity in the group's institution, actual group metadata, command-bound MFA and deterministic idempotent persistence. Display names supplied by clients do not decide identity. Classrooms bind group revision and teacher grant generation; old rows without these fields cannot supply active classroom access. Current scoped administration can revoke an old enrollment invitation, but reading/publishing/enrolling requires current group scope. Cross-institution invitations do not consume capacity.

Authentication supplies a server-only verified persisted session-source attribute. Native group/classroom/tutoring/case/representative/excuse routes reject matching institutional IDs instead of selecting accounts by ID. Native channels receive the full current actor and native source; provider courses remain limited to their actual institutional assigned teachers/enrolled students. An institutional administrative role cannot list every provider course without an explicit resource/tenant adapter.

Representatives channels use institution-specific identifiers (`channel-representatives:<base64url institution>`). Old global-channel posts are retained but cannot be used as an authorized tenant channel; operators must review any data migration separately. Representative appointments derive actual student/group labels and institution/period/expiry/revision. Legacy or expired appointments do not confer channel access, and restoring period labels does not reactivate them. Existing acceptance, decline and revocation lifecycles remain.

Excuse listing/review validates current native administration capability and actual group institution; an old membership cannot enable student submission across institutions. Private tutor cases still require actual current tutor assignment, including for SUPER_ADMIN.

## Manual schedule authority
Native manual-schedule HTTP routes require a current native MANAGE_ACADEMICS actor and command-bound MFA. The owner must be an actual active verified academic account or actual group in the same institution. Subject/teacher/group labels derive from an existing assigned native classroom; caller-supplied labels do not create academic identity. Scope revisions, deterministic operation IDs and single-document Mongo CAS prevent duplicate or stale changes. Cancellation retains a scoped tombstone and audit revision instead of deleting provenance. Legacy rows without explicit institution scope require protected migration, not name/ID inference. Pure formatting/projection helper tests do not imply that COORDINATOR has administrative endpoint authority. CI now requires 24 real Mongo tests including independent concurrent schedule operators.

### School entry QR and presence

Administrative school QR routes use a verified native account, the actual MANAGE_ACADEMICS institution capability, an enabled institution directory entry, and a real MFA proof bound to the typed command. Creation has a deterministic actor/operation ID; only the winning creation returns the raw token. Persisted documents store the hash, tenant, strict integer revision and bounded secret-free creation/revocation audit. Reissuing a request never returns the secret again; regeneration requires a new bound MFA command and retains the revoked predecessor before deterministic replacement continuation. This is not a claimed multi-document transaction.

Mongo revision CAS prevents stale usage updates from reviving a revoked QR. Strict missing/fractional revisions and missing institution metadata deny native use. Unscoped historical codes and school days remain retained as evidence; they do not grant current native campus authority. Native school entry additionally requires a live verified STUDENT account whose persisted institution matches the managed QR. Client network declarations remain networkVerified=false.

An operator may explicitly map the old configured fixed QR to its actual institution with SCHOOL_PRESENCE_INSTITUTION_ID. Missing or mismatched mapping denies native fallback. A token recognized in the managed catalog never falls back to that legacy hash: current revocation, expiration and tenant scope are authoritative. No environment values, credentials or databases were modified by this migration. Institutional-source campus identities need an explicit source adapter; selecting a native account by matching a provider ID is forbidden. Android connection and native attendance occurrence integration remain tracked follow-up work before V12 release.
